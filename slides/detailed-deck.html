Problem

The Photon entry of the NanoAOD trigger-object table only accepts HLT objects from the collection hltEgammaCandidates. The sub-leading leg of HLT_Diphoton30_22_R9Id_OR_IsoCaloId_AND_HE_R9Id_Mass90 and _Mass95 is built from hltEgammaCandidatesUnseeded. The collection test is applied before the filter bits are computed, so every object carrying the unseeded last-filter labels is dropped and its bits can never appear. The sub-leading photon of the main H to gamma gamma triggers cannot be trigger-matched from NanoAOD. Confirmed on thirteen NanoAOD files from v9 to v15 and 2026 data (16_0_X): not a single photon object with an unseeded bit.

Solution

Accept both e/gamma collections in the Photon selection string, exactly as the Electron selection does. Because objects are kept only when they set at least one photon bit, and the only photon-bit filters on the unseeded collection are the three diphoton ones, the output changes only in events that fired those triggers. Bit numbers and documentation stay the same. NANO re-made with the fix sets the unseeded bits in all 10453 Mass90 events of the MC test file and changes nothing else; in 2026 data (16_0_4_patch2) in all 308. The fix branch is on the fork; no pull request is open yet.

The three dead bits are the unseeded last filters of the Diphoton30_22 paths (two bits) and of the 2018 and 2022 Diphoton30_18 paths (one bit). The rest of the deck shows the evidence step by step.

A leg-by-leg efficiency, a trigger-matched tag-and-probe, or a HiggsDNA-style matching of both photons needs the bit of the last filter of each leg. For the sub-leading leg of the diphoton triggers that bit is never set, so the match always fails.

The table is produced by TriggerObjectTableProducer from the unpacked MiniAOD trigger objects. Each object type has its own selection string; an object is written only if it passes that string and sets at least one bit of that type.

The filter bits are the only way to know which HLT filter an object passed in NanoAOD, because the filter labels themselves are not stored. Everything therefore depends on the per-type selection admitting the objects that carry the labels.

Two producers, two RecoEcalCandidate collections, two distinct trigger objects in the event even when they describe the same photon. The trigger summary, PAT and MiniAOD keep the collection name with each object. NanoAOD decides per object type which collection names it accepts, and that decision is where the photon table goes wrong.

Both producers come from the same menu file (CMSSW_13_3_1_patch1, HLT_FULL_cff.py); the only difference is the supercluster input, L1-seeded versus unseeded. The sub-leading photon often has no L1 seed above threshold of its own, which is why double-photon paths reconstruct it unseeded.

Names exactly the two collections and copies the Electron selection of PR 41827. A wildcard would also match (next slide) but would admit any future collection with that prefix.

What changes

Unseeded objects enter the photon branch; with the skip flag only those that set a photon bit are written, and the only photon-bit filters on the unseeded collection are the three diphoton ones. A seeded twin in the same direction is merged with OR-ed bits.

What does not

Bit numbers, documentation strings, the other object types and the event content. Only events that fired a diphoton trigger gain photon rows.

Appendix C: how the defect was born, survived and was found

7 to 8 Feb 2023

PR 40711 adds the six diphoton photon bits for the next NanoAOD production. The Photon selection is not touched, so the three unseeded bits are dead from day one. In CMSSW_13_0_0; v12 is made with 13_0_13.

31 May to 8 Jun 2023

PR 41827 gives the Electron selection the unseeded collection and the CaloIdL_MW unseeded bit. Photons are not revisited. In CMSSW_13_3_0, so NanoAOD v13 has it for electrons only.

Nov to Dec 2023

13_3_X backports for v13 (43292 from 43247, 43286, 43470 and others); CMSSW_13_3_1_patch1 produces NanoAOD v13 for Summer22, 22EE, 23, 23BPix MC and the 16Dec2023 2022 data.

13 to 18 Mar 2025

PR 47594 / 47601: hltEG45 and hltEG50 EB bits and the VBF wildcard are added and filterBits becomes 64-bit (CMSSW_15_0_2). The unseeded bits move to 16, 17 and 19, still dead. v15 inherits them.

4 Nov 2026

This investigation: cause located, confirmed on master ed35654b1 and the 16_x branches, whole-table scan done, one-line fix committed on top of upstream master, pull request text ready. No open upstream PR or issue on the subject.

Dates are the creation and merge dates returned by the GitHub search API. Between CMSSW_13_0_0 and 13_0_1 the photon pt threshold moved from 20 to 15 GeV; that change did not touch the collection test either.

The electron fix of June 2023 is the moment the photon defect could have been caught: the same author added the unseeded collection to one selection and wrote in the pull request that it was the collection on which the unseeded leg is selected. The photon list, four months old at that point, kept its single collection.

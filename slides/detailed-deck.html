Problem

The Photon entry of the NanoAOD trigger-object table only accepts HLT objects from the collection hltEgammaCandidates. The sub-leading leg of HLT_Diphoton30_22_R9Id_OR_IsoCaloId_AND_HE_R9Id_Mass90 and _Mass95 is built from hltEgammaCandidatesUnseeded. The collection test is applied before the filter bits are computed, so every object carrying the unseeded last-filter labels is dropped and its bits can never appear. The sub-leading photon of the main H to gamma gamma triggers cannot be trigger-matched from NanoAOD. Confirmed on twelve NanoAOD files from v9 to v15: not a single photon object with an unseeded bit.

Solution

Accept both e/gamma collections in the Photon selection string, exactly as the Electron selection does. Because objects are kept only when they set at least one photon bit, and the only photon-bit filters on the unseeded collection are the three diphoton ones, the output changes only in events that fired those triggers. Bit numbers and documentation stay the same. NANO re-made with the fix sets the unseeded bits in all 10453 Mass90 events of the test file and changes nothing else. The fix branch is on the fork; no pull request is open yet.

The three dead bits are the unseeded last filters of the Diphoton30_22 paths (two bits) and of the 2018 and 2022 Diphoton30_18 paths (one bit). The rest of the deck shows the evidence step by step.

A leg-by-leg efficiency, a trigger-matched tag-and-probe, or a HiggsDNA-style matching of both photons needs the bit of the last filter of each leg. For the sub-leading leg of the diphoton triggers that bit is never set, so the match always fails.

The table is produced by TriggerObjectTableProducer from the unpacked MiniAOD trigger objects. Each object type has its own selection string; an object is written only if it passes that string and sets at least one bit of that type.

The filter bits are the only way to know which HLT filter an object passed in NanoAOD, because the filter labels themselves are not stored. Everything therefore depends on the per-type selection admitting the objects that carry the labels.

Two producers, two RecoEcalCandidate collections, two distinct trigger objects in the event even when they describe the same photon. The trigger summary, PAT and MiniAOD keep the collection name with each object. NanoAOD decides per object type which collection names it accepts, and that decision is where the photon table goes wrong.

Both producers come from the same menu file (CMSSW_13_3_1_patch1, HLT_FULL_cff.py); the only difference is the supercluster input, L1-seeded versus unseeded. The sub-leading photon often has no L1 seed above threshold of its own, which is why double-photon paths reconstruct it unseeded.

Each leg ends in two alternative last filters, wrapped in cms.ignore() so that failing one does not stop the path; the leg combiner on the seeded leg ORs them, and the pair filter requires one object from each leg. NanoAOD defines one bit per last filter. Only the seeded ones can ever be set.

    if kind == "path":

def bits_of(doc, obj):
    # Total: time O(len(doc)), space O(n_bits)
    bits = {}
    for chunk in doc.split("; "):                               # list scan O(len) | each per-object chunk
        if not chunk.strip().endswith(" for " + obj):          # -                | keep only this object's chunk
            continue
        for match in BIT_ENTRY.finditer(chunk):                # regex O(len)     | each "N => description"
            bits[int(match.group(1))] = match.group(2).strip()  # dict insert O(1) | bit -> description
    return bits


def find_bit(bits, name):
    # Total: time O(n_bits), space O(1)
    for bit, description in bits.items():                      # dict scan O(n)   | first bit naming the filter
        if name in description:                                # substring O(len) | description contains name
            return bit
    return None


def has_bit(filter_bits, bit):
    # Total: time O(n_obj), space O(n_obj)
    shifted = filter_bits >> np.uint64(bit)                    # jagged op O(n)   | move bit to position 0
    return (shifted & np.uint64(1)) == 1                       # jagged op O(n)   | per-object bit set?


def count_objects(ids, filter_bits, object_id, bit, event_mask=None):
    # Total: time O(n_obj), space O(n_obj)
    if bit is None:
        return None
    selected = (ids == object_id) & has_bit(filter_bits, bit)  # jagged mask O(n) | objects of this id with bit
    if event_mask is not None:
        selected = selected & event_mask                       # broadcast O(n)   | only in chosen events
    return int(ak.sum(selected))                               # reduction O(n)   | number of objects

def bit_counts_per_id(ids, filter_bits, n_bits, skip_id):
    # Total: time O(n_obj * n_bits), space O(n_obj)
    flat_ids = ak.to_numpy(ak.flatten(ids))                    # array O(n)       | all object ids
    flat_bits = ak.to_numpy(ak.flatten(filter_bits))           # array O(n)       | all object bit words
    counts = {}
    for object_id in np.unique(flat_ids):                      # sort O(n log n)  | each object type
        if object_id == skip_id:
            continue
        words = flat_bits[flat_ids == object_id]               # mask O(n)        | bit words of this type
        per_bit = [int(((words >> np.uint64(b)) & np.uint64(1)).sum()) for b in range(n_bits)]
        counts[str(int(object_id))] = {str(b): c for b, c in enumerate(per_bit) if c > 0}
    return counts


def event_contents(arrays, skip_id=None):
    # Total: time O(n_obj log n_obj), space O(n_obj)
    contents = {}
    rows = zip(arrays["run"], arrays["luminosityBlock"], arrays["event"],
               ak.to_list(arrays["TrigObj_id"]), ak.to_list(arrays["TrigObj_filterBits"]),
               ak.to_list(arrays["TrigObj_pt"]))
    for run, lumi, event, ids, words, pts in rows:             # loop O(n_events) | one event at a time
        objects = [(i, int(w) & 0xFFFFFFFFFFFFFFFF, p) for i, w, p in zip(ids, words, pts) if i != skip_id]
        contents[(int(run), int(lumi), int(event))] = sorted(objects)  # dict O(1)  | key -> sorted objects
    return contents

Validation: relval workflows before and after, and a direct count of the new bits

1. Standard workflows with a NANO step

Done in CMSSW_16_1_3 (5 November): 12452.0 (10 events) and 141.046 (100 events). No exceptions; identical to the clean release except DQM timing histograms. The relval NANO has no TrigObj, so the photon selection is not exercised.

2. Differences seen in the fix test

NANO re-made from one MiniAOD file (17760 events): unseeded bits in all 10453 Mass90 events (zero before), pt from 22.04 GeV; every other object type identical in all events.

3. Already measured on files

Twelve NanoAOD files, v9 to v15 (4-5 November): unseeded photon bits 0 in all of them, all controls as predicted (results/REPORT.md).

# count photon objects with the unseeded bits, per path

import uproot, awkward as ak, numpy as np
t = uproot.open("nano.root")["Events"]
path = "HLT_Diphoton30_22_R9Id_OR_IsoCaloId_AND_HE_R9Id_Mass90"
a = t.arrays(["TrigObj_id", "TrigObj_filterBits", path])
ph    = a["TrigObj_id"] == 22
bits  = ak.values_astype(a["TrigObj_filterBits"][ph], np.uint64)
fired = a[path]
for bit in (16, 17):   # 14, 15 for NanoAOD v12 to v14
  has = ak.any(((bits >> np.uint64(bit)) & np.uint64(1)) == 1,
               axis=1)
  print(bit, int(np.sum(has & fired)), "of", int(np.sum(fired)))

Before the fix both counts are 0 by construction. After it they must be of the order of the number of events that fired the path. Measured in the fix test: every one of the 10453 Mass90 events has a photon with at least one of the two bits.

For an existing v12 to v14 file the loop runs over bits 14 and 15 and filterBits is a 32-bit integer; the uint64 cast is harmless there. The script is also in NOTES.md section 8.1 of the notes repository.

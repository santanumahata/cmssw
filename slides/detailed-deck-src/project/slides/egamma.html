Two e/gamma candidate collections at HLT: L1-seeded and unseeded

hltEgammaCandidates (seeded)

Superclusters built only in regions around L1 e/gamma candidates. Used by the leading leg (Et > 30 GeV, L1 match required) and by nearly every single-photon and single-electron path.

fragment.hltEgammaCandidates = cms.EDProducer(
  "EgammaHLTRecoEcalCandidateProducers",
  scHybridBarrelProducer = cms.InputTag(
    'hltParticleFlowSuperClusterECALL1Seeded',
    'hltParticleFlowSuperClusterECALBarrel' ),
  scIslandEndcapProducer = cms.InputTag(
    'hltParticleFlowSuperClusterECALL1Seeded',
    'hltParticleFlowSuperClusterECALEndcapWithPreshower' ),
  recoEcalCandidateCollection = cms.string( "" ) )

hltEgammaCandidatesUnseeded

Superclusters built over the whole ECAL, with no L1 requirement. Used for the sub-leading object of double-object paths (Et > 22 GeV here), which may have no L1 seed of its own.

fragment.hltEgammaCandidatesUnseeded = cms.EDProducer(
  "EgammaHLTRecoEcalCandidateProducers",
  scHybridBarrelProducer = cms.InputTag(
    'hltParticleFlowSuperClusterECALUnseeded',
    'hltParticleFlowSuperClusterECALBarrel' ),
  scIslandEndcapProducer = cms.InputTag(
    'hltParticleFlowSuperClusterECALUnseeded',
    'hltParticleFlowSuperClusterECALEndcapWithPreshower' ),
  recoEcalCandidateCollection = cms.string( "" ) )

Two producers, two RecoEcalCandidate collections, two distinct trigger objects in the event even when they describe the same photon. The trigger summary, PAT and MiniAOD keep the collection name with each object. NanoAOD decides per object type which collection names it accepts, and that decision is where the photon table goes wrong.

Both producers come from the same menu file (CMSSW_13_3_1_patch1, HLT_FULL_cff.py); the only difference is the supercluster input, L1-seeded versus unseeded. The sub-leading photon often has no L1 seed above threshold of its own, which is why double-photon paths reconstruct it unseeded.

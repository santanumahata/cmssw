What analyses see: every Run 3 NanoAOD file, and no sub-leading match for the diphoton triggers

Datasets

Data: 2022 (PromptNano v10/v11, 22Sep2023 v12, 16Dec2023 v13), 2023 (22Sep2023 v12), 2024 (prompt v14), 2025 (prompt v15) and the v15 re-NANO of 2022 to 2024. MC: Run3Summer22, 22EE, 23, 23BPix at v12 and v13, Summer24 at v15, and the v15 re-NANO of all of them. Any Run 2 input re-processed with v12 or later.

Frameworks

NanoAOD-based photon matching (HiggsDNA-style workflows, the HYgammaRunIII legend that lists bits 16 and 17 as the legs, FLAF configurations, custom NanoAOD setups) finds no object for the sub-leading leg. MiniAOD-based flashgg reads the pat trigger objects directly and is unaffected.

Existing files cannot be repaired. The unseeded objects were never written; no post-processing can recover them. Only a new NANO pass with the fix restores the information.

A leading photon that also passes the unseeded leg merges with its unseeded twin (same direction) and carries both bits; a sub-leading photon appears as a new row.

The schematic rows are made up to show the structure; pT values and the number of rows will differ event by event. GitHub code search finds the unseeded filter names in 16 files outside cms-sw: analysis legends and configurations, custom NanoAOD producers, and flashgg's MiniAOD validation script.

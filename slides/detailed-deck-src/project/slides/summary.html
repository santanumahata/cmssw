Problem

The Photon entry of the NanoAOD trigger-object table only accepts HLT objects from the collection hltEgammaCandidates. The sub-leading leg of HLT_Diphoton30_22_R9Id_OR_IsoCaloId_AND_HE_R9Id_Mass90 and _Mass95 is built from hltEgammaCandidatesUnseeded. The collection test is applied before the filter bits are computed, so every object carrying the unseeded last-filter labels is dropped and its bits can never appear. The sub-leading photon of the main H to gamma gamma triggers cannot be trigger-matched from NanoAOD. Confirmed on ten NanoAOD files from v9 to v15: not a single photon object with an unseeded bit.

Solution

Accept both e/gamma collections in the Photon selection string, exactly as the Electron selection does. Because objects are kept only when they set at least one photon bit, and the only photon-bit filters on the unseeded collection are the three diphoton ones, the output changes only in events that fired those triggers. Bit numbers and documentation stay the same. The fix is committed locally on top of today's upstream master and applies cleanly; nothing is pushed yet.

The three dead bits are the unseeded last filters of the Diphoton30_22 paths (two bits) and of the 2018 and 2022 Diphoton30_18 paths (one bit). The rest of the deck shows the evidence step by step.
